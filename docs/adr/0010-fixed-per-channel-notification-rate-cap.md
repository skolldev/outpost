# Fixed per-channel notification rate cap

Outpost caps Notification delivery at a fixed ten per rolling minute per Channel, and the cap is deliberately not configurable: a limit that stops a bad deploy minting dozens of new Issues from flooding a chat channel is a product invariant rather than an install knob, and exposing it as a setting would invite operators to raise it to the value that reproduces the flood. Occurrences beyond the cap are recorded as `suppressed` rows in the same per-channel history rather than dropped silently, so an Admin who wonders why a channel went quiet finds the answer where they are already looking. The cap is scoped per channel — one flooded destination never suppresses another — and applies only to matched trigger deliveries, so an Admin verifying a Channel with a test-send is never refused by a limit the test is trying to diagnose. Counting and deciding are serialized per channel by a transaction-scoped advisory lock, because concurrent virtual-thread deliveries otherwise race between the count and the insert and overshoot the cap; the lock is released at commit, before the HTTP send, so it never spans the network and a slow receiver cannot delay another occurrence's decision.
